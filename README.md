# Диктофон совещаний (Desktop Audio Recorder)

Кроссплатформенное десктопное приложение для автоматизированной записи аудио в формате WebM (Opus) с графическим интерфейсом на PyQt6, встроенным HTTP REST сервером управления, интеграцией в системный трей, локальной БД SQLite, системой ротации и автоматической отправкой данных по HTTP/HTTPS POST.

---

## 1. Возможности и архитектура

- **Отказоустойчивая запись аудио**: Потоковый захват через `sounddevice` и непрерывная кластеризация фреймов в контейнер WebM (`libopus`, 48 кГц) с помощью `PyAV`. При аварийном завершении или отключении питания файл сохраняется и воспроизводится вплоть до секунды обрыва.
- **Локальный HTTP REST API**: Встроенный сервер (по умолчанию порт `8765`) для интеграции с внешними CRM/ERP/ботами:
  - `POST /start` — старт сессии с метаданными совещания.
  - `GET /stop` — безопасная финализация записи и отправка на вебхук.
  - `GET /show` — разворачивание окна приложения на передний план.
  - `GET /status` — текущее состояние диктофона.
- **Поддержка HTTP и HTTPS вебхуков**: Автоматическая фоновая отправка `multipart/form-data` (аудиофайл WebM + метаданные в JSON) с поддержкой самоподписанных сертификатов (`verify_ssl: false`).
- **Защита от повторного запуска**: Использование Windows Named Mutex и сокета — предотвращает дублирование процессов и разворачивает уже запущенный экземпляр.
- **Современный UI**: Нативная темная тема Windows 11 Fluent UI, информативный таймер, шкала уровня звука (VU-метр), единая кнопка управления и системный трей.
- **Локальное хранилище**: База данных SQLite с историей записей, статусами доставки и автоматической ротацией старых файлов.
- **Автоматическая сборка .exe**: Скрипт `build.py` на базе PyInstaller и готовый GitHub Actions Workflow для сборки релиза в облаке.

## 3. Быстрый старт из исходников

### Требования
- Python 3.10, 3.11 или 3.12 (64-bit)
- Windows 10 / 11

### Установка зависимостей
```powershell
# Создание виртуального окружения
python -m venv .venv

# Активация
.\.venv\Scripts\activate

# Установка библиотек
pip install --upgrade pip
pip install -r requirements.txt
```

### Запуск
```powershell
python main.py
```
*(Или дважды кликните по файлу `run.bat`)*

## 4. Сборка исполняемого файла (.exe)

Сборка упаковывает приложение в один автономный бинарный файл `dist/Dictaphone.exe`, которому не требуется установленный Python.

### Локальная сборка
Запустите:
```powershell
python build.py
```
Или выполните батник:
```cmd
build_exe.bat
```
Результат будет сохранен в папку `dist/Dictaphone.exe`.

### Автоматическая сборка через GitHub Actions
В репозитории уже настроен пайплайн `.github/workflows/build-exe.yml`:
1. При каждом `push` в ветку `main` запускается сборка на раннере `windows-latest`.
2. Готовый `.exe` публикуется в артефактах GitHub Actions.
3. При создании тега версии (например, `git tag v1.0.0 && git push --tags`) файл автоматически прикрепляется к новому GitHub Release.

## 6. HTTP REST API справочник

Сервер слушает порт `8765` (по умолчанию `0.0.0.0:8765`).

### Эндпоинты

| Метод | URL | Описание |
|---|---|---|
| `POST` | `/start` | Запуск записи совещания с телом JSON |
| `GET`  | `/stop`  | Остановка текущей записи и выгрузка |
| `GET`  | `/show`  | Развернуть окно приложения из трея |
| `GET`  | `/status`| Получить статус (активна ли запись, метаданные) |

### Пример запуска записи через cURL
```powershell
curl.exe -X POST "http://127.0.0.1:8765/start" -H "Content-Type: application/json; charset=utf-8" -d '{"id":"meeting-101","title":"Планерка","agenda":[{"name":"Вопрос 1"}],"participants":[{"name":"Иван"}]}'
```

### Статус-коды
- `200 OK`: Успешное выполнение команды.
- `400 Bad Request`: Некорректный синтаксис JSON или пустой запрос.
- `404 Not Found`: Неизвестный маршрут.
- `405 Method Not Allowed`: Недопустимый HTTP-метод.
- `409 Conflict`: Запись уже активна (`RECORDER_BUSY`).
- `422 Unprocessable Entity`: Отсутствуют обязательные поля (`id`, `title`).
- `500 Internal Server Error`: Внутренняя ошибка сервиса.
